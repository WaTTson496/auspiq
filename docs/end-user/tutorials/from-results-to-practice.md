# 結果から練習へ

このレッスンでは、解析結果または生成結果を `practice` に渡し、AuspiQ の3本柱がつながっていることを確認します。ここでは細かい調整よりも、「どの保存物が次の作業に渡せるか」を体験することを重視します。

## 前提

- [first-analysis.md](./first-analysis.md) または [first-generation.md](./first-generation.md) を終えている
- 解析結果 JSON または生成結果 JSON が手元にある

## 1. 解析結果から練習を始める

`predict full` の出力を使う場合は、保存した JSON をそのまま指定します。

```bash
auspiq practice --file results/auspiq_full_YYYYMMDD_HHMMSS.json
```

ここで見るもの:

- 問題文が1文字ずつ表示されること
- 解析結果由来の `analysis_points` があると、閾値を超えた位置で自動停止できること
- Enter、`c`、`a`、`n`、`q` で進行を操作できること

この挙動は、「解析結果には押しどころに関する情報がある」ということの表れです。`practice` は単に文字を流しているのではなく、解析済みデータに含まれる位置情報を使って練習体験を作っています。

Enter の意味は状態で変わります。

- 表示中の Enter: プレイヤーが解答権を獲得して一時停止
- 解答権獲得後の Enter: 解答入力へ進む
- 一時停止中で解答権未確定の Enter: 表示再開
- `c`: 解答権を手放して問題文の表示を続ける

## 2. 生成結果から練習を始める

`generate --format json --output generated.json` のように保存した JSON も、そのまま渡せます。

```bash
auspiq practice --file generated.json
```

ここで見るもの:

- 生成結果でも練習を始められること
- 生成結果には `analysis_points` がないため、解析結果のときと同じ自動停止は起きないこと
- 入力元によって練習体験が変わること

この違いは不整合ではなく、入力元の役割の違いです。解析結果ベースの練習は「どこで押すか」を扱い、生成結果ベースの練習は「新しい問題で回数をこなす」ことを扱います。

## 3. フィードバックを保存する

練習結果を後で見返したいときは `--feedback-out` を付けます。

```bash
auspiq practice --file generated.json --feedback-out feedback/practice.json
```

ここで見るもの:

- `summary` と `entries` を持つ JSON が保存されること
- 押した位置、所要時間、正誤、入力元メタデータが記録されること

フィードバック JSON を保存すると、練習をその場限りで終わらせず、後で見返せる作業ログにできます。AuspiQ が各段階で保存物を残す設計なのは、このように作業をつなげたり振り返ったりする余地を残すためです。

## 4. このレッスンで得たもの

- AuspiQ では、解析結果と生成結果のどちらも次の練習へ渡せる
- ただし、入力元が違うと練習時の挙動も違う
- 画面表示だけでなく JSON 保存物を残しておくと、作業をつなげやすい
