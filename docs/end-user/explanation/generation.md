# 生成が多くの制御を公開している理由

`generate` に設定項目が比較的多いのは、単にオプションを増やしたいからではありません。AuspiQ の生成は、題材選択、プロンプト構築、API 呼び出し、品質検証という段階の積み重ねでできているため、どこをどの程度制御するかを切り分けているからです。

`question_type` や長さ制約は、出力文そのものに近い制御です。`mode`、`stage`、`facet-weight`、`code-weight` は、題材の選ばれ方や品質基準に近い制御です。これらが分かれていると、結果が気に入らないときに「何を直せばよいか」を考えやすくなります。

`quality_report` や `selection` が返るのも同じ理由です。AuspiQ は、生成結果を単に 1 問出して終わるのではなく、なぜその問題が出たかを後で追えるようにしています。特に複数生成や条件調整では、この補助情報がないと再現や比較が難しくなります。

生成を使うときに見落としやすいのは、「どの制御がどの層に効くか」です。長さや question type は最終的な問題文の形に近い制御ですが、mode や stage や weight 調整は、その前段の題材選択や通過条件に近い制御です。つまり、出てきた文が気に入らないとき、必ずしも prompt だけを直せばよいわけではありません。

また、quality report があるからといって、AuspiQ が真偽や妥当性を完全に保証しているわけではありません。品質検証はヒューリスティックです。だからこそ、AuspiQ は score だけでなく issue の内訳を返し、どこが怪しいかを人間が読めるようにしています。これは「自動で完璧に良問を出す」設計ではなく、「比較と調整がしやすい生成支援」の設計です。

設定項目が多いのは複雑さの押し付けでもありますが、その代わり、少しずつ条件を変えて挙動を観察できるという利点があります。AuspiQ の生成は、完成品の自動販売機というより、条件付きの生成実験を支えるツールだと考える方が実態に近いです。
