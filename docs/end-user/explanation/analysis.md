# 解析に複数モードがある理由

`predict single` と `predict full` は、同じ推測機能でも答えたい問いが違います。

`predict single` が向いているのは、「この断片だけ見えているとき、いま何が有力か」を知りたい場面です。対して `predict full` は、「問題全体を通したとき、どの位置で押し判断が立ちやすいか」を知るためのものです。前者は一瞬の判断、後者は問題全体の押しどころの観察です。

出力の読み方も違います。`single` では候補と蓋然性を見ることが中心ですが、`full` では位置ごとの変化を見ることが中心です。`full` の結果が `practice` に渡せるのは、この位置情報が練習体験の設計に使えるからです。

LLM ベースの推測は、確率モデルの厳密な意味での確率ではありません。AuspiQ では、数値を絶対評価ではなく、候補比較や押し位置比較のための目安として読む方が実務的です。

この違いは、UI 上の都合ではなく、利用者の判断単位の違いでもあります。`single` はその場の断片判断を助け、`full` は問題全体の流れを見直すための材料を与えます。同じ問題でも、「今ここで押すか」を知りたいのか、「この問題はどこで押せるタイプか」を知りたいのかで、必要な出力は変わります。

また、`batch` が別にあるのも同じ理由です。複数問題を処理するとき、1問ごとの対話的な表示や細かい観察よりも、同じ形の結果をまとめて作ることが重要になります。AuspiQ の解析は、「1 回の対話」から「まとめて観察する作業」まで、用途ごとに出力の粒度を変えています。

解析結果を読むときは、候補順位だけでなく、`total_probability` の動きや、どの位置から有力候補が安定するかを見ると実務的です。数値そのものを信仰するより、「どこから候補が絞れてくるか」という変化を見る方が、押し判断や練習設計には役立ちます。
