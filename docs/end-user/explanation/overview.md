# AuspiQ の捉え方

AuspiQ は、1つのコマンドを繰り返し叩く道具ではなく、解析、生成、練習をつなぐワークフローとして理解すると使いやすくなります。

解析は、問題文の途中や全文から「どの時点で押せそうか」を見るための機能です。生成は、新しい問題を作り、その選択理由や品質評価も一緒に残す機能です。練習は、それらの保存物を入力にして体験を作る機能です。

この3本柱の間にあるのは JSON 保存物です。AuspiQ がローカルファイルを多く残すのは、1回ごとの実行を記録し、後で別の作業につなげるためです。結果を画面だけで消費せず、保存物をワークフローの部品として扱うと全体像が見えやすくなります。

典型的な流れは 1 通りではありません。たとえば、既存問題の押しどころを見たいなら `predict full -> practice` が自然です。新しい問題で回数を増やしたいなら `generate -> practice` が自然です。大量の問題を比較観察したいなら `predict batch` や複数生成が入ります。重要なのは、最初にコマンドを決めるのではなく、今ほしい成果物が何かを考えることです。

また、AuspiQ はローカル保存物が多い分、初見では複雑に見えます。しかしこれは、CLI が冗長だからではなく、1 回の実行結果を後で別の作業に使えるようにしているからです。`results/`、`logs/`、`~/.auspiq.json`、`~/.auspiq-jobs.json` を「実行の副産物」ではなく「作業の部品」として理解すると、構造がすっきり見えてきます。

逆に、画面表示だけを見て使うと、各コマンドがばらばらの機能に見えやすくなります。AuspiQ を使いこなすうえで大事なのは、コマンドの名前を暗記することより、「どの保存物が次の行為へ渡せるか」を把握することです。
