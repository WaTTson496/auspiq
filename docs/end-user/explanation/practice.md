# 入力形式で練習がどう変わるか

`practice` は1つのコマンドですが、どの JSON を入力するかで体験が変わります。

解析結果を入力すると、`analysis_points` を使って「ここで押し得だったか」を反映した練習になります。しきい値による自動停止も、この情報があるから成立します。これは、押し位置の感覚を鍛えたいときに向いています。

生成結果を入力すると、問題文と解答はあるものの、押し位置情報はありません。そのため、練習はより手動寄りになります。これは、問題ストックを増やして回したいときや、押し位置評価よりも出題体験を重視したいときに向きます。

同じ `practice` でも、解析結果ベースは「押しどころの検討」、生成結果ベースは「新しい問題で回数をこなす」寄りです。入力元を変えるのは、モード変更ではなく練習目的の変更だと考えると判断しやすくなります。

この違いは、practice が単独で完結した練習システムではなく、前段の成果物に依存して体験を作るコマンドだからです。解析結果が rich なのは、押し判断に関する情報まで持っているからで、生成結果がシンプルなのは、新しい問題そのものを供給することが主目的だからです。

また、threshold や speed は万能の難易度調整ではありません。threshold は主に解析結果ベースの練習で意味を持ち、speed は表示体験全体に効きます。どちらも「難しいか簡単か」だけでなく、「何を鍛えたいか」に応じて選ぶ必要があります。

practice を使うときは、コマンドの形よりも、入力元がどんな情報を持っているかを見る方が本質的です。押し位置を鍛えたいなら解析結果、出題数を増やしたいなら生成結果、という見方を持つと使い分けやすくなります。
