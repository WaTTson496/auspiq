# 再現性に成果物が必要な理由

AuspiQ の生成は LLM 呼び出しを含むため、同じ条件でも完全再現は簡単ではありません。そのため、`run_id`、prompt、selection、weight、timings、quality report といった artifact を残す設計にしています。

これらは単なるデバッグログではなく、「なぜこの結果になったか」を後から比較するための材料です。特に生成条件の調整やデータ変更の評価では、問題文だけでは不十分で、どの selection や quality issues が出ていたかも必要になります。

SQLite store が用意されているのも同じ発想です。現状の CLI では未接続ですが、設計意図としては生成結果を後から検索、比較、再利用できるようにするためのものです。
